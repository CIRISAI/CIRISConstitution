## Aside found while verifying (not in Gemini's list)

The generated matcher refuses the deferral family's own wire strings. `cc_namespace_match.match_family` on `deferral:request:v1` returns `missing_version_segment`, and the same for `deferral:response:approved:v1` and `identity_amendment:v1`; the vectors pin that refusal as expected (`manifests/namespace_match_vectors.json:2818–2821`: `"dimension": "deferral:response:approved:v1" … "refusal": "missing_version_segment"`) and pin `deferral:request:v1:v1` / `deferral:response:approved:v1:v1` / `identity_amendment:v1:v1` as the strings that resolve (:2752, :2788, :4066). The registry segments for `deferral:request:v1` are `[literal deferral, literal request, literal v1]`, so the generator read the prefix's trailing `:v1` as a literal and still demands R3's version tail. `custody:ack:v1` (family `custody:{kind}`, P:250 "wire `custody:ack:v1`") resolves correctly because its prefix is written without the tail. Part 3 names `deferral:response:approved:v1` as the wire string at P:329 (`authorized_by` cites "the `deferral:response:approved:v1` row") and P:515. **P** — either write the three families' prefixes as `deferral:request`, `deferral:response:{outcome}`, `identity_amendment` (the registry then appends the R3 tail) or teach the generator that a prefix ending in a version segment is already versioned; regenerate the vectors either way.
