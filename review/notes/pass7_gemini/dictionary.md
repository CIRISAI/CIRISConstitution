# The Dictionary (ciris_constitution-1.0-rc12-dictionary.pdf, 109 pages)

**Care score:** 3  
**One-line verdict:** The volume has a rigorous, self-enforcing mechanical architecture, but before 1.0 it needs a targeted cleanup pass to fix a mangled LaTeX table cell, resolve a direct internal contradiction on `key_grant` cardinality and withdrawal, and strip transitional migration notes and references to external platforms.

## Strengths
- **Generated, non-drifting namespace architecture:** The rule that `manifests/namespace_registry.json` is built directly from CC 3.1 tables and verified against reference match vectors (`manifests/namespace_match_vectors.json`) prevents prose-to-code drift by construction (p. 1, p. 27, p. 30).
- **Explicit byte-level canonicalization:** Hash preimages and byte structures are pinned with zero ambiguity, such as the v2 JCS preimages for `SkillImportManifest` and per-locale Merkle trees (p. 8–9) and the four-step Reticulum destination-hash algorithm (p. 60–61).
- **Clear separation of wire vs. variant spelling:** Closed enumerations (`LegalBasis`, `WrapAlgorithm`, `GrantScope`) explicitly separate PascalCase specification labels from lowercase `snake_case` wire bytes, preventing fail-secure drops on emergency takedown notices (p. 45–48).
- **Tightly reasoned safeguard inversions:** Complex human-factors edge cases—such as adult incapacity failing open to liberty (`capacity_assurance:*`, p. 95–101) versus minor protection failing closed to restriction (`age_assurance:*`, p. 93–95, p. 101–106)—are specified with clear state machines and anti-capture rules.

## Weaknesses
- **Broken table rendering in `deferral:response:{outcome}:v1`:** In the CC 3.1.9.3 table, an unescaped pipe `|` in `{outcome} ∈ approved | rejected` broke the LaTeX tabular alignment, spilling `rejected. Attester = the WA's own key...` into the Polarity column, pushing `Open emitter.` into the Description column, and leaving the actual polarity (`signed`) missing (p. 36).
- **Contradiction on `key_grant` supersession vs. withdrawal:** The `key_grant` struct definition states that `rotation_chain` is the prior grant lineage for the same `(content_sha256, recipient_key_id)` pair and that mass-retirement uses a fresh `key_grant` that "supersedes the prior grant" (p. 46, p. 48). Yet the paragraph immediately above it states that `key_grant:{axis}:v1` rows are unioned by identity, "once admitted is never removed by a later one," and "a re-emitted wrap with the same identity is idempotent" (p. 48).
- **Transitional / deprecated schemas left in normative text:** Section 3.3.9 opens by stating that `organization`, `org_membership`, and `partner_record` "remain registered and in force until an amendment (CC 4.5.1) retires them onto its rows" (p. 66), and CC 3.1.3 registers two `self:delegates_to` rows as "Legacy label, closed... Registered so stored and in-flight rows resolve" (p. 12).
- **Transitional implementation artifacts in prose:** The `identity:occurrence_revocation` row refers to a migration log artifact ("the migration's count line names it for the owner to re-propose", p. 11), and CC 3.4.10 refers to an interim schema ("target schema; see CC 5.3.1 for the interim using a `registry_witnesses` table", p. 92).
- **Comparative / external project references:** Prose includes parenthetical editorializing about external standards and projects, such as "(not RFC 6962's split...)" (p. 6, p. 9), "(the lesson of deployed purpose-limitation systems: point checks and out-of-band audits are the mechanism that fails to laundering)" (p. 84), and naming commercial platforms like "Medium / Substack / WordPress / Ghost / Tumblr" (p. 74) and "Eventbrite / Meetup / Lu.ma" (p. 76).
- **Unanchored prose numbers and rules:** In `preserve_request`, the prose parenthetically states "(five years is a best practice...)" without a register or citation anchor (p. 24); in `custody:ack:v1`, it mandates that "a responsive device re-acknowledges about daily" ("about daily" is untestable in a normative section, p. 19).

## Opportunities
- **Escape the pipe in `deferral:response:{outcome}:v1` (p. 36):** Fixing the single unescaped `|` in the markdown source will restore the table columns and ensure the namespace generator parses the polarity of `deferral:response:{outcome}:v1` (`signed`) instead of `"rejected. Attester = ..."`.
- **Reconcile `key_grant` lifecycle prose (p. 46–48):** Clarify whether `key_grant` rotation creates a new axis identity (e.g. via `ratchet_version` or `epoch`) that coexists in the union, or whether `supersedes` is permitted on `key_grant` rows despite the "never withdrawn / never removed by a later one" rule on p. 48.
- **Retire `organization`, `org_membership`, and `partner_record` before 1.0 (p. 66–68):** Since p. 66 already maps every field of these three legacy Portal kinds onto `affiliations`, `membership:*`, and `licensure:*`, cutting the legacy schemas before 1.0 avoids shipping a 1.0 Constitution with a pre-announced deprecation.

## Threats
- **Parser/generator failure or corrupt manifest entry on `deferral:response` (p. 36):** Because `manifests/namespace_registry.json` is extracted from the CC 3.1 tables (p. 1, p. 27), the broken table row for `deferral:response:{outcome}:v1` on p. 36 either causes the generator to record a garbage polarity string or proves the PDF was rendered from markdown that disagrees with the generator's expectations.
- **Implementer deadlock on `key_grant` rotation (p. 46–48):** An implementer reading p. 46 and the bottom of p. 48 will build `rotation_chain` supersession for compromised recipients; an implementer reading the middle of p. 48 will treat same-axis re-emissions as idempotent no-ops and refuse supersession/withdrawal.
- **Hostile-reviewer critique of pre-deprecated 1.0 primitives (p. 11, p. 12, p. 66, p. 92):** Shipping rc/migration notes ("the migration's count line", "until an amendment retires them", "Legacy label, closed", "target schema... interim using a `registry_witnesses` table") in a 1.0 Constitutional release exposes the text as a snapshot of an in-flight codebase refactor rather than a clean constitutional baseline.

## Rendering
- **Broken table row / pipe-escaping failure (p. 36):** In `deferral:response:{outcome}:v1`, `{outcome} ∈ approved | rejected` splits across columns, putting `\` at the end of the first line, `Open emitter.` on the second line of Description, and the rest of the description inside the Polarity column.
- **Mid-word hyphenless line breaks in narrow table cells (p. 11, p. 75):** `SignedIdentityOccurr` / `enceRevocation` (p. 11) and `compositeW` / `ithTrainedAlgorithmicMedia` (p. 75) wrap mid-word without a hyphen.
- **Detached section-reference numbers across line breaks (p. 4, 5, 7, 10, 12, 21, 22, 23, 32, 34, 35, 37, 41, 78, 93, 101):** Cross-references frequently break right after a period at the end of a line, leaving a bare digit at the start of the next line (e.g., `CC 3.` / `2`, `CC 3.` / `4.1`, `CC 5.` / `4.6`, `CC 4.5.` / `13`).
- **Awkward line wrapping in code blocks (p. 63, 75, 95, 97):** Long comments in code blocks wrap onto unindented continuation lines (e.g., `never a score value` and `allow list (below)` on p. 63; `over the bytes...`, `allocation`, `CC 3.1.3.4`, `absent in clear` on p. 75; `mandatory):` on p. 95; `order:` on p. 97).
- **Inconsistent table layouts for registry rows (p. 12, 16, 21, 27, 31, 37–38, 41–43):** While most registry rows render in 3- or 4-column tables, several render as stacked bold-key paragraphs (`lineage_witness:{stage}` on p. 12, `membership:{stage}` on p. 16, `rendezvous:route:v1` on p. 21, `detection:correlated_action:{axis}` on p. 31–32, all of `3.1.9.4` on p. 37–38, and `3.3.1` on p. 41–43).
